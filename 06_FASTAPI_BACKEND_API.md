# Quantum QEC AI — FastAPI Backend Guide

## 1. Backend purpose

The backend turns the research code into an API.

Main framework:

```text
FastAPI
```

Entry point:

```text
backend/main.py
```

---

# 2. Starting point

The application creates:

```python
app = FastAPI(...)
```

and registers:

```text
CORSMiddleware
```

and the API router.

# 4. CORS

The uploaded backend currently configures:

```text
allow_origins = ["*"]
allow_credentials = False
allow_methods = ["*"]
allow_headers = ["*"]
```

This allows browser requests from the separately hosted frontend.

For a production security review, unrestricted origins should be reconsidered.

# 8. GET /experiments

Returns stored experiments.

Supports filters for:

```text
rounds
physical_noise_probability
measurement_noise_probability

```

and optional sorting.

---

# 9. GET /experiments/best

Returns the best stored experiment according to a requested metric.

Default:

```text

```

---

# 10. GET /experiments/worst

Same idea, but returns the lowest result according to the selected metric.

---

# 18. Feature adapter

The trace service contains:

```text
_LogicalTargetDecoderAdapter
```

Why?

Because two components represent the feature vector differently.

The quantum integration creates:

```text
all syndrome bits
+
all detection-event bits
```

The Random Forest expects:

```text
s1,s2,d1,d2
```

per round.

The adapter converts:

```text
Integration format
       |
       v
Adapter
       |
       v
Random Forest format
```

This avoids changing the existing decoder.

# 21. Beginner explanation

Think of FastAPI as a receptionist.

The user says:

```text
"Run this QEC experiment."
```

FastAPI receives the request and passes it to the research engine.

Then the result comes back:

```text
Experiment result
```

FastAPI converts it into JSON and sends it to the frontend.
